# 仕様：入力方式と画面構成

ステータス：**確定**／2026-10-25

## 1. 入力方式

### 1.1 候補

| 方式                        | 👍                                                                       | 👎                                                          |
| --------------------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------- |
| A. CLIのみ                  | 現場で使うスキルがそのまま身につく。無駄な操作をコマンド単位で数えられる | 初心者が最初の一歩で詰まる。スマホでは打ちにくい            |
| B. ボタン・カードのみ       | 誰でも触れる。スマホ向き                                                 | 本物のgitを打てるようにならない。「全部できる」と両立しない |
| C. ハイブリッド（**推奨**） | 両方のいいとこ取り                                                       | 実装が少し増える                                            |

### 1.2 推奨：C. CLIを正とし、補助UIは「コマンドを組み立てる」だけ

- **実行されるのは常にターミナルに入ったコマンド**。ボタンを押しても直接は実行されない。入力欄にコマンド文字列が入り、プレイヤーがEnterを押して初めて実行される
  - → プレイヤーは毎回、実際のコマンドを目にする
  - → 無駄な操作の判定がコマンド単位でぶれない
- **補助UI（チップ）**：状況に応じてよく使うコマンドを並べる。例：変更ファイルがある → `git add <file>`、ステージ済み → `git commit -m ""`
- **補完**：Tabでサブコマンド・ブランチ名・ファイル名を補完する。↑↓で履歴をたどる
- **補助輪を段階的に外す**（演出と連動）

| 章                 | 補助UI                                   | 演出                                           |
| ------------------ | ---------------------------------------- | ---------------------------------------------- |
| 序盤（新人編）     | チップあり、日本語ヒントあり             | 先輩がやさしく教えてくれる                     |
| 中盤（独り立ち編） | チップは基本コマンドのみ。ヒントは申請制 | 上司「いつまで補助輪付けてんだ」でチップが減る |
| 後半（先輩編）     | チップなし。ヒントを使うと後輩に見られる | 後輩の前でヒントを見ると信頼が少し下がる       |
- **ファイル編集**：エディタ画面で直接編集する（作業ツリーの変更、コンフリクト解消）
  - コンフリクトの印（`<<<<<<<` など）をハイライトする
  - 「現在の変更／取り込む変更を採用」のボタンは**序盤だけ**用意し、後半は手で消させる
- **`git commit` を `-m` なしで打った場合**：コミットメッセージ用のエディタを模擬表示する
  - 隠し要素：vim風の画面が開き、抜け方がわからないとチャットに先輩が「`:wq` だよ…」と書き込む（gitあるあるネタ）

### 1.3 シナリオ外のコマンド

- 対応していないコマンドやオプションは、**本物風のエラーを出さない**。かわりに「このシミュレータでは未対応：〇〇」と明示する（嘘を教えないため）
- `rm -rf` などgit以外のシェルコマンドは `ls`, `cat`, `cd`, `echo`, `touch`, `rm`（ファイル単位）だけ対応する。危険なもの（`rm -rf /` など）はネタとして上司が飛んでくる演出にしてもよい

## 2. 画面構成

### 2.1 構成要素

| エリア                   | 役割                                                                                                                           |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| ヘッダー                 | 章、作中の時刻（例：金曜 17:45）、後輩の信頼ゲージ、上司の機嫌ゲージ                                                           |
| 社内チャット（Slack風）  | ミッション指示、NPCの発言、怒りのメッセージ、後輩からのDM「先輩…やっちゃいました…」。物語の主な舞台                            |
| リポジトリの可視化       | コミットグラフ（ローカルとorigin/*を表示し、originとの差を見せる）＋4領域ビュー（作業ツリー → ステージ → ローカル → リモート） |
| ファイル                 | ファイルツリーとエディタ。状態の印（M / A / U / ?）                                                                            |
| ターミナル               | 入力、出力、補助チップ                                                                                                         |
| カットイン（重ねて表示） | 大事な演出のときだけ全面に出す（上司の激怒、後輩のキラキラ顔など）                                                             |

### 2.2 PCレイアウト（推奨）

```
┌──────────────────────────────────────────────────────────┐
│ 第3章 金曜17:45 │ 後輩の信頼 ■■■■□ │ 上司の機嫌 ■□□□□      │
├──────────────┬────────────────────────┬──────────────────┤
│ ファイル       │ コミットグラフ             │ #dev-team チャット │
│  src/        │  (local / origin)       │ 部長: おい…       │
│  .env  U     │                         │ 後輩: すみません   │
│ ──────────── │ ─────────────────────── │ ...              │
│ エディタ       │ 4領域ビュー               │                  │
│              │ 作業 → ステージ → ローカル → リモート │                  │
├──────────────┴────────────────────────┴──────────────────┤
│ $ git status                                              │
│ [git add .env] [git restore --staged]    ← 補助チップ      │
└──────────────────────────────────────────────────────────┘
```

- 右にチャットを常に出す。物語とミッションが途切れない
- 中央はgitの状態。学習の主役
- 下はターミナル。操作の主役

### 2.3 スマホ

- 下部のタブで切り替える：チャット／グラフ／ファイル／ターミナル
- ターミナルの補助チップを常時表示する（打つ量を減らす）
- **PC優先で作り、スマホは「遊べる」レベル**を目標にする

## 3. 演出レイヤーの置き場所（画面側）

| 演出           | 表現                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 上司の激怒     | 画面が揺れる → カットイン → チャットに長文で説教 → 機嫌ゲージが下がる                        |
| 後輩のまなざし | ヘッダーとチャットのアイコンの表情が段階的に変わる（キラキラ → 普通 → 不安 → 疑い → 虚無）   |
| 後輩の独り言   | 無駄な操作が続くとチャットに「…（入力中）」が出ては消える。追い打ちで「先輩、それさっきも…」 |
| 解決したとき   | 後輩のカットイン「先輩かっこいい…！」                                                        |

## 4. 決定事項（2026-10-25）

- [x] 入力方式：C. ハイブリッド（実行は常にCLI。補助チップはコマンドを組み立てるだけ）
- [x] 端末：**PC優先**。スマホはタブ切り替えで遊べるレベル
- [x] ビジュアル：**Slack風の社内チャット＋山場だけ立ち絵カットイン**
- [x] 補助輪：**章ごとに段階的に外す**（上司のセリフと連動）
- [x] フリーモード（サンドボックス）：**最初の版に入れる**
