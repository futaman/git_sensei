# 仕様：見た目と、ゲームとしてのわかりやすさ（『Good Job!』の方向）

ステータス：案（未確定）／2026-10-31

> **この文書の位置づけ**
> - docs 03_spec_input_and_layout（確定）が**画面の構成要素と置き場所**を決めた
> - docs 06_guide_direction の 6章が**見た目の方向**（『Good Job!』のように、整った世界をやらかしでめちゃくちゃにする）を決めた
> - この文書は、その方向を**画面ひとつひとつの形・色・動き**に落とし、あわせて「ゲームとして、いま何をすればいいかがわかる」ための決まりを足す
> - エンジン（docs 02）と演出エンジン（docs 04）の仕組みは変えない。変えるのは `src/ui/` と、チップ・セリフの出し方（`src/scenarios/`）だけ

## 0. 結論（先に3つ）

1. **「管理画面」をやめて「オフィスのフロア」にする**。コミットグラフと4領域ビューを、箱と玉が動く1枚の絵（フロア）にまとめる。数字と表は結果画面まで出さない
2. **いつでも「いま何をすればいいか」が1行で見える**。しごとカード・HEAD の位置・ゴールの付箋を、画面の決まった場所に固定する。導入は20秒で最初のコマンドが打てる長さにする
3. **キャラクターを絵にする**。絵文字と漢字1文字のアイコンを、丸い頭と点の目の2頭身の人形（SVG）に変える。表情の段階（まなざし・機嫌）は、この人形で見せる

## 2. 『Good Job!』から借りるもの

| 『Good Job!』 | このアプリでは | 借りない理由があるもの |
|---|---|---|
| 1フロアが1画面に収まる。スクロールしない | ステージは**1画面・スクロールなし**（1280×720 以上）。フロア（中央）に全部ある | — |
| 目的はピクトグラム1つと、運ぶ先 | 「今日のしごと」は**アイコン＋1行**。ゴールは「届け先」に ✓ がつく付箋 | — |
| 物が動いて結果がわかる。説明の文はない | add で箱が台に乗る、commit で玉になる、push で玉が右へ行く。**コマンドのたびにフロアで必ず1つ動く** | 物理演算は使わない（docs 06 §6.2）。動きは決まった形にして、リプレイで同じにする |
| 評価は「かかった時間」と「損害額」 | 結果画面はこの2軸＋手数、最後にランクのハンコ | — |
| 整った世界ほど、壊したときにおかしい | ふだんは全部グリッドにそろえる。やらかすと箱がこぼれ、玉が落ち、**復旧するまで残る** | 人を投げる・ぶつける類の笑いは使わない。怒りは静かに（docs 06 G2） |
| 壁を壊したほうが早く見える | 間違ったほうが手数が少なく見える誘惑（docs 07 K2）。チップは誘惑も正解も**言わない** | — |
| 建物の階ごとにステージ | メニューは**ビルのフロア案内**。1章＝1F、2章＝2F、3章＝3F、外伝＝B1 | — |
| 無口。音と動きで伝える | 音は任意（docs 06 §6.3）。**音がなくても全部わかる**ように作る | — |

## 3. ステージ画面

### 3.0 骨組み

```
┌──────────────────────────────────────────────────────────────────────┐
│ [📦] calc.ts の修正を main に入れる  〆18:00 │ 17:45 │ (田中) (部長) │ 始末書 ≡ │  帯 56px
├────────────┬──────────────────────────────────────┬─────────────────┤
│ ファイル     │ フロア                                │ 付箋（ゴール）    │
│  📦 README │  レール                               │ ☐ origin の main に│
│  📦 calc   │   ○──○──◉ ←あなた（HEAD）  ┊ ☁ origin │ ☐ 田中さんの修正を │
│  📦 index  │   ───────────────────────┊────────  │─────────────────│
│ ─────────  │  机（作業ツリー）    台（ステージ）      │ # dev           │
│ エディタ     │  [📦] [📦]         [ ]               │ (部長) 今日中に… │
│            │                                      │ (田中) 僕もさっき…│
│            │                                      │ (あなた) …       │
├────────────┴──────────────────────────────────────┴─────────────────┤
│ $ git status                                                          │  ターミナル
│ [git status] [git log --oneline]                   Tab 補完 ・ ↑↓ 履歴 │  ≥ 200px
└──────────────────────────────────────────────────────────────────────┘
```

- 列は `260px / minmax(0,1fr) / 320px`。**中央の `<main>` にも `grid-cols-[minmax(0,1fr)]` を入れる**。フロアの中身は中で横スクロールさせ、列の外へはみ出さない（問題4）
- 行は `56px / minmax(0,1fr) / minmax(200px,30vh)`
- 1024px 未満では、右の列をフロアの上に重ねるタブにする（docs 03 §2.3 のスマホの考え方）。1024〜1279px では右の列を 280px にする
- **ふだんの画面はすべて 8px グリッドにそろえる**。やらかしたときに崩れるものだけがグリッドを外れる

### 3.1 帯（ヘッダー）

左から順に。

| 部品 | 形 | 変えること |
|---|---|---|
| しごとカード | 白い紙（角丸 12px、下に 2px の影）。左に**しごとのアイコン**（📦 届ける、🔍 調べる、🧹 片づける、🔑 止める のどれか。ステージが選ぶ）、右に1行の `mission.task`、小さく `〆 due` | 「今日のしごと」の見出し文字と `title` の行を消す。`title` はカードにマウスを乗せたときだけ |
| 時計 | 等幅の太字 28px。締切の近さで色（docs 06 §5 の `deadline` のとおり） | 「締切 18:00」の小さな行は消し、しごとカードの `〆` に寄せる |
| 田中（後輩） | 人形の顔 40px ＋ 名前 ＋ **玉5つ**（信頼） | **増減の数字（+5 / −15）を消す**。玉は増えるとき 1つずつポン、減るときしぼんで消える（0.3秒） |
| 黒岩部長 | 人形の顔 40px ＋ 名前 ＋ **顔の枠の色**だけ（機嫌） | **横棒のゲージと数字を消す**。爆発寸前は顔が小さく震える（いまの `stage-tremble` のまま） |
| ステージの数 | ピル型（待機室 3人、図鑑 4/10 など） | 形だけピル型にそろえる |
| 始末書 | 赤い点つきの書類アイコン。枚数は点の中 | 文字ボタンをやめる |
| ≡ | メニュー（やり直す、道場を元に戻す、時間制限なし、メニューへ） | 帯に並んでいる4つのボタンを1つにまとめる。**ヒントは帯から外し、チャットの早瀬先輩のところへ**（3.4） |

### 3.2 フロア：レール（コミットグラフの描き直し）

いまの `CommitGraph` の配置計算（`layout.ts`）はそのまま使い、**描き方だけ**変える。

| 要素 | 形 |
|---|---|
| レール | 太さ 3px、角の丸い線。色は `--line`（うすいグレー）。ブランチが分かれるところは今と同じ曲線 |
| 玉（コミット） | 半径 12px。白い塗り、2px のふち。ふちの色はブランチの色。**HEAD の玉は塗りつぶし**。追加されるときにはねる（拡大 1.0 → 1.12 → 1.0、0.25秒） |
| あなた（HEAD） | **HEAD の玉の上に、プレイヤーの人形が立つ**。ブランチ名は人形の足元の札（`main`）。detached HEAD のときは、人形がレールのない宙に浮く（頭の上に `?`） |
| ブランチの札 | ピル型。レールの色と同じ。HEAD → main の矢印は使わず、人形が立っている札が現在地 |
| origin の印 | origin/* から届く玉に、小さな**雲のマーク** ☁ をつける。`origin/main` の札は雲つきのピル。「サーバーにある」が玉ごとにわかる |
| 玉の下の文字 | ハッシュ 7桁（等幅 11px、うすい）＋件名 10文字。マウスで全文 |
| 差の印 | `origin/main` の札の横に「↑1」（push 待ち）「↓1」（取り込み待ち）を小さく。これは数字だが「いくつ運ぶか」なので許す |
| 空のとき | レールだけを薄く引いて、人形が最初の玉を待っている絵 |

- 雲の印は**手元の `origin/*` の記録**（最後に fetch したとき）で描く。サーバーの本当の状態は fetch するまで見せない（前回のプレイテストの「fetch するまで手元の記録は古い」）
- push が弾かれたときは、玉が右の点線にぶつかって**はね返る**（0.4秒）。いまの「↩ push が弾かれた」の吹き出しは残す。雲の玉が手元にないことを見せるのが目的
- force push で他人の玉を消したときは、その玉が**レールから弾き飛ばされてフロアの床に落ちる**（いまの ⚾ の代わり）。落ちた玉は**復旧するまで床に残る**（docs 06 §6.2）

### 3.3 フロア：机と台（4領域ビューの描き直し）

「作業ツリー → ステージ → ローカル → リモート」のうち、**ローカルとリモートはレール（3.2）に吸収**する。残る2つを、机と台として描く。

```
 机（手元のファイル）                  台（次のコミットに入る）
 ┌─────────────────────┐   add →    ┌──────────────┐   commit →  ○（レールへ）
 │ [📦] [📦!] [📦M]     │            │ [📦M]        │
 │ README calc  index  │   ← restore│              │
 └─────────────────────┘            └──────────────┘
```

| ファイルの状態 | 箱の形 |
|---|---|
| 変更なし | 閉じた箱。うすく描く（机の奥に並ぶ）。数が多ければ「ほか 3 箱」とまとめる |
| 変更あり（M） | 箱のふたが少し開き、**オレンジの付箋**が貼ってある |
| 未追跡（U） | 白い箱に `?`。テープが貼られていない |
| 削除（D） | ぺしゃんこの箱の輪郭だけ |
| コンフリクト | 箱から `<<<` `>>>` の**矢印が2本刺さっている** |
| ステージ済み | 台の上に乗り、テープが貼られる。机にはその箱の影だけ残る |

- 箱は 36×28px、角丸 6px、ふち 2px。下にファイル名を 10px、長ければ末尾だけ（`…/calc.ts`）
- `add` で箱が机から台へ**すべる**（0.3秒）。`restore --staged` で台から机へ戻る
- `commit` で台の箱が**ひとつにまとまって玉になり、レールにポンと乗る**（0.5秒）。台が空になる
- `push` で玉が右へすべり、雲の印がつく（0.5秒）。`fetch` / `pull` で右から玉が来る
- **コマンドのたびに、フロアで必ず1つ動く**。何も変わらないコマンド（空振り）では、机の上に「…」が 1秒出て消える
- 机と台の見出し（「作業ツリー」「ステージ」）は 11px で薄く残す。言葉は覚えてほしいので消さない。矢印の下の `add` `commit` の文字も残す

### 3.4 右の列：付箋とチャット

**付箋（ゴール）**

- 黄色い付箋（`--sticky`）を右上に**ピンで留めた**形。ゴールの文を1行ずつ、先頭に ☐
- 達成すると ☐ が ✓ に変わり、付箋の端が少し持ち上がる（0.3秒）。全部そろうと付箋が**緑のハンコ「済」**をもらう
- 見出し「ゴール（18:00 までに、ぜんぶ ✓ でクリア）」は「〆18:00」だけにする。締切の欄が文のステージ（「問い合わせが増える前に」）は、`〆` をつけずそのまま書く（前回のプレイテストの「かっこが二重」）

**チャット（# dev）**

| 変えること | 形 |
|---|---|
| アバター | 漢字の四角をやめ、人形の顔（5の章）を 28px で。表情は**その時点の段階**（まなざし・機嫌）を映す |
| **自分の発言** | 選択肢を押したら、その文を**あなたの発言として流す**（右寄せ、緑の枠）。NPC の返事はその後 |
| **地の文** | 話し手 `narration` を足す。アバターも名前もなし、中央寄せ、うすいグレーの斜体。「（田中のモニターに付箋が貼られた）」はこれで出す。`system` は通知やボットの発言に戻す |
| 入力中 | 「田中が入力中…」の文字をやめ、アバター＋**跳ねる点3つ**の吹き出し |
| rage | 色と大きさは変えない（docs 06 §5）。入力中の間を倍にする。いまの赤い背景は消す |
| 選択肢 | 下にピル型のボタン。見出しは「#dev に書く」 |
| **ヒント** | チャットの下、選択肢の横に「早瀬先輩に聞く（5分）」のピル。押すと**早瀬先輩の発言として**ヒントが流れる。帯のボタンは消す |

### 3.5 ターミナル

docs 06 §6.1 のとおり、**ここだけ暗い色で、本物の道具として扱う**。崩さない。

- 色は `#1E1F24`。文字は 13px の等幅。いまのままでよい
- チップはピル型（角丸 999px、ふち 1px）。並ぶ数は**最大 5**
- チップの**中身の決まり**は 7章の R7（答えを言わない）
- 日本語のヒント行（「ヒント：origin に、手元にないコミットがあります」）は残す。先頭の「ヒント：」を 💡 にして行頭をそろえる

### 3.6 左の列：ファイルとエディタ

- ファイル一覧の各行に、机と同じ箱の小アイコン（16px）と状態の付箋。`M` `U` `D` `!` の文字は残す（覚えてほしい言葉）
- エディタはいまのまま。コンフリクトの印のハイライトだけ、箱に刺さる矢印と同じ色にする

Tailwind v4 の `@theme` に入れる（`src/ui/index.css`）。**色は意味のあるところにだけ使う**。

|---|---|---|

| `--panel` | `#FFFFFF` | 紙、カード、箱 |
| `--line` | `#D8D5CC` | ふち、レール |

| `--branch` | `#4D8DF0` | ブランチ、雲（origin）、田中 |
| `--warn` | `#F0A531` | 変更あり、締切 warning、部長の不機嫌 |

| `--senpai` | `#8B6CF0` | 早瀬先輩 |
| `--term` | `#1E1F24` | ターミナル |

| 形 | 値 |
|---|---|
| 角丸 | 紙・カード 12px、箱 6px、ピル 999px |
| 線 | ふち 2px、レール 3px、細いふち 1px（チップ） |
| 影 | `0 2px 0 var(--line)`（紙が1枚浮いている程度。ぼかしは使わない） |

- **ダークモードは作らない**。ターミナルだけが暗い、という対比が見た目の芯なので、画面全体を暗くすると消える

## 5. キャラクター

docs 06 §6.1「丸い頭と点の目だけの、2頭身の人形」を SVG で描く。`src/ui/components/cast/Face.tsx` に `<Face who stage size />` として置く。

| | 髪・しるし | 色 | 表情（5段階） |
|---|---|---|---|
| 田中（後輩） | 前髪ぱっつん、メモ帳 | `--branch` | 憧れ ✨目／期待 まる目／不安 眉下がり／疑心 細目／虚無 目の光なし（`stage` は `TrustStage`） |
| 黒岩部長 | 短髪、腕組み | `--ink` | 上機嫌 口角／普通 一文字／不機嫌 眉寄せ／爆発寸前 こめかみに線、震える／雷 目が白い（`MoodStage`） |
| 早瀬先輩 | 無造作、マグカップ | `--senpai` | 常に半目で軽い。ヒントのときだけ指を立てる |
| あなた | 髪なし（プレイヤー）、ネームプレート | `--go` | レール上に立つ。detached で `?`、やらかしで汗 |

- 頭の上のマーク：`!`（驚き）`?`（迷子）`…`（無言）`💧`（汗）`✨`（感心）。Cue の `face` と `mood` から決める
- 表情が**上がるときは 0.2秒でパッと、下がるときは 0.8秒かけて**（docs 06 §5）
- 絵文字（🤩 😐 ⚡）はすべてこの人形に置き換える。雷のカットインの ⚡ だけは記号として残してよい

## 6. 導入・結果・メニュー

### 6.1 導入（出勤）

いまのモーダルをやめ、**フロアの上でそのまま始める**。目標は「20秒以内に最初のコマンドを打てる」（docs 06 §7）。

1. 帯のしごとカードが上から降りてくる（0.4秒）。アイコン、1行、`〆`
2. チャットに導入のセリフが**1つずつ**流れる（入力中 → 吹き出し）。3つまで。クリックで早送り
3. `situation` の文は**地の文**としてチャットに流す（アバターなし）。モーダルの箇条書きはやめる
4. 付箋がピンで留まる（ゴール）
5. ターミナルに `terminalIntro`（「まずは git status」）が出て、入力欄にフォーカス

- 「時間制限なしで遊ぶ」は、帯の ≡ の中と、**メニューのステージカードの裏**（6.4）に置く。導入では聞かない
- 2回目以降（そのステージの記録がある）は、1〜4 を**1秒でまとめて**出す

### 6.2 プレイ中の重ねもの

| Cue | いまの形 | 変えること |
|---|---|---|
| `cutin`（rage / sparkle / despair） | 画面の真ん中を横切る帯 | **フロアの下 3分の1に帯**（docs 06 §5）。ターミナルは隠さない。人形の全身と一言。1.2秒、キーで飛ばせる |
| `thunder` | 全画面の黄色い点滅 | 全画面のままでよい。点滅を1回にし、部長の人形（雷の顔）を中央に。2秒 |
| `report` | 右上に「始末書 1」のボタンが増える | 書類が**右上からすべり込み、帯のアイコンに赤い点**（docs 06 §5）。モーダルは開かない |
| `shake` | 画面全体が揺れる | フロアだけ揺れる。ターミナルとチャットは揺らさない |
| push の結果 | グラフ上の吹き出し | 3.2 のはね返り・雲の印に置き換える。吹き出しは残す |

### 6.3 結果（業務報告書）

```
┌──────────────────────────────┐
│ 業務報告書   金曜17:45、定時前の push │
│                              │
│ かかった時間  17:45 ──●── 17:58 〆18:00 │
│ 手数         ○○○○○ ●●       （最短 5）│
│ 損害額       ¥0                │
│ 始末書       なし              │
│                              │
│ (田中)「さすがです」            │
│ (部長)「…よし」                │
│                        ╭───╮ │
│                        │ A │ │ ← ハンコ
│                        ╰───╯ │
│ [次のしごとへ] [もう一度] [メニュー] │
└──────────────────────────────┘
```

- 行は**1つずつ**出る（0.4秒おき）。損害額はカウントアップ。大きいほど長く重く（docs 06 §5 の `rank`）
- 手数は玉で見せる。par までを白い玉、超えたぶんを灰色の玉。par を**下回った**ときは「最短より少ない」と小さく出す（前回のプレイテスト P8）
- ランクのハンコは最後にポンと押される（いまの `stage-stamp`）。S のときだけきらきら
- **「次のしごとへ」を足す**（問題10）。章の最後なら「次の章へ」
- 「完了時刻（締切 18:00）」の書き方は「17:58 〆18:00」にそろえる。締切が文のステージでは `〆` をつけずに文をそのまま

### 6.4 メニュー（フロア案内）

```
┌───────────────────────────────────────────────┐
│ git_sensei                                     │
│ 頑固な部長と、まっすぐな後輩のいる職場で、git を体で覚える │
│                                               │
│  3F │ 先輩編      [3-1 田中の3時間 🔒] [3-2 .env]    │
│  2F │ 独り立ち編   [2-1][2-2][2-3][2-4][2-5]        │
│  1F │ 新人編      [1-1 A][1-2 S][1-3 ▶][1-4]        │
│  B1 │ 道場・練習   [やらかし道場] [フリーモード] [始末書図鑑] │
└───────────────────────────────────────────────┘
```

- **ビルの断面**。章が階、ステージが部屋。下の階（1F）から始まる
- 部屋のカード：番号、題、しごと1行、`〆`。遊んだ部屋には**ランクのハンコ**。次に遊ぶとよい部屋に ▶（記録のない、いちばん小さい番号）
- ロックはしない（どこからでも遊べる）。ただし未実装のステージ（3-1、3-3〜3-5）は 🔒 で「準備中」と出し、どんなコマンドを覚えるかだけ書く
- カードにマウスを乗せると裏返り、「覚えること」「最短 n 手」「時間制限なしで始める」が出る
- B1 に**始末書図鑑**の入口を置く。集めた始末書（全ステージ横断）を並べる。未収集は影だけ。保存は `records.ts` と同じ仕組み（この端末だけ）

## 7. わかりやすさの決まり

画面を作るとき、どの場面でも確かめること。

| # | 決まり | 確かめ方 |
|---|---|---|
| R1 | **いま何をすればいいかが1行で見える** | 帯のしごとカード。どの場面でも隠れない |
| R2 | **いまどこにいるかが見える** | レールの上の人形。detached は宙に浮く |
| R3 | **コマンドのたびに、フロアで必ず1つ動く** | 動かない＝空振り。机の上に「…」 |
| R4 | **どこまで来たかが見える** | 付箋の ✓。全部で「済」のハンコ |
| R5 | **プレイ中に数字を出さない** | 信頼・機嫌の増減、手数、損害額は結果画面だけ。例外は時計、`↑1 ↓1`、道場の損害額 |
| R6 | **1画面、スクロールなし** | 1280×720 以上で、縦横ともスクロールしない。中央の列は外へはみ出さない |
| R7 | **チップは答えを言わない** | 開始時は見るコマンド（`status` `log --oneline` `diff` `show`）だけ。**解き方のコマンドは、先輩に聞いた後か、一度間違えた後**。道場は空 |
| R8 | **自分の発言はチャットに残る** | 選択肢を押した文が、あなたの発言として流れる |
| R9 | **地の文に名前をつけない** | `narration` はアバターなし |
| R10 | **演出で手を止めない** | 雷以外は入力欄が生きている。次のコマンドを打ったら、残りの演出は最後の状態へ飛ぶ（docs 06 §5.1） |
| R11 | **終わったら次がある** | 結果に「次のしごとへ」 |
| R12 | **音がなくてもわかる** | 効果音を切っても、R3 の動きだけで何が起きたかわかる |
