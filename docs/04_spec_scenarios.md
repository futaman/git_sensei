# 仕様：シナリオとやらかし演出

ステータス：案（未確定）／2026-10-25

## 1. 演出の方針

| #   | 方針                                                                             | 理由                                                                                 |
| --- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| P1  | 状況はできるだけ具体的にする（時刻、ファイル名、コミットメッセージ、誰がいるか） | 「あるある」と感じた瞬間に、学ぶ動機が生まれる                                       |
| P2  | 時間で追い込む（作中の時計が締め切りに向かって進む）                             | 焦っているときこそ正しい手順を選べるか、を体験させる                                 |
| P3  | 失敗を避けさせるのではなく、**わざと失敗させる**                                 | 競合にない差別化ポイント（docs 01 の 3章）                                           |
| P4  | 怒りは怒鳴り声ではなく「静けさ・既読・敬語」で表す                               | パワハラ描写に見えない。しかも一番怖くて笑える（docs 01 の「演出の線引き」への答え） |
| P5  | 「ヤバい」と「ダサい」を分ける                                                   | 危険な操作はヤバ度、無駄な操作は後輩の信頼。評価の軸が混ざらない                     |

## 2. メインステージ：「本日26時リリース」

### 2.1 状況

- 木曜 23:48 にスタート。ヘッダーの時計は `25:12` のように、日付をまたいでも24時以降の書き方で進む
- 部長は「先に帰る。26時までに出しといて。**信じてるから**」と言って21時に帰宅済み。信頼されているのがかえってプレッシャー
- 後輩は終電を逃して隣の席で寝落ち。ときどき起きて画面をのぞく
- ヘッダーに「エナドリ 残り1本」。押すと眠気がリセットされる（1回だけ）

### 2.2 オープニング（強制のやらかし）

眠気のまま `git add . && git commit -m "ううう"` を打ってしまう（カットシーン）。コミットの中身：

```
src/payment/calc.ts        ← 本命の修正
src/payment/calc.ts.bak
debug.log                  (48MB)
node_modules/              (12,483ファイル。昼のマージで .gitignore が消えていた)
memo.txt                   「部長の"信じてる"は呪い」
```

### 2.3 ゴールと学ぶこと

- **ゴール**：26時までに `fix: 決済手数料の端数処理を修正` を1コミットだけ origin に push する
- **学ぶこと**：`reset --soft HEAD~1`、`restore --staged`、`rm --cached`、`.gitignore`、`commit --amend`

### 2.4 時間の仕組み

| 操作                                      | 作中の経過時間                                                       |
| ----------------------------------------- | -------------------------------------------------------------------- |
| 状態を見るコマンド（status / log / diff） | 0分（確認は良い習慣なので罰しない。docs 02 の 3.4 と同じ方針）       |
| その他のコマンド                          | 1分                                                                  |
| エラーになったコマンド                    | 2分                                                                  |
| ヒントを見る                              | 5分                                                                  |
| node_modules ごと push                    | 18分（`Writing objects: 3%` がじわじわ進む。急がば回れを体で覚える） |
- 25時を過ぎると眠気で入力がタイポする：`gti stauts` → 後輩「先輩、gtiってなんですか…」

### 2.5 落とし穴

- `reset --hard HEAD~1` を打つと calc.ts の修正まで消える。後輩が飛び起きて「…いま、消えました？」。reflog で救えるが時間を食う

### 2.6 エンディング

| 条件                       | 結果                                                            |
| -------------------------- | --------------------------------------------------------------- |
| 25:40 までに完了           | 朝 7:02、部長から「👍」だけ届く（最高評価）                     |
| 25:59 に完了               | 後輩「ギリギリでしたね…」                                       |
| 26:01 以降                 | 朝のメール「昨夜の件、10時に5分ください」                       |
| memo.txt ごと push（隠し） | 部長「memo.txt 読んだ。呪いを解きます。今日は定時で帰りなさい」 |

## 4. わざと間違えるステージ：「やらかし道場」

### 4.1 設定と流れ

- 先輩「研修用のリポジトリを用意した。本番でやったら終わることを、今日ここで全部やっとけ」
- 流れ：やらかす → ヤバ度判定のカットイン → 図鑑に登録 → 復旧して「成仏」させる → 次へ
- 自由に操作できるサンドボックスに近い。ミッションの指定はなく、図鑑の空き枠がヒントになる

### 4.2 ヤバ度の段階

| Lv  | 名前     | 意味                                     | 演出                                                                                                                                                     |
| --- | -------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | ヒヤリ   | ローカルだけで済み、すぐ戻せる           | 後輩だけが気づいて小さく「…あ」                                                                                                                          |
| 2   | 冷や汗   | ローカルで消えたが reflog で救える       | 画面が一瞬揺れる。後輩「せ、先輩？」                                                                                                                     |
| 3   | 始末書   | 共有先に出て、他の人に影響が出る         | チャットに部長「**ちょっといいか**」。既読を付けるまで点滅する                                                                                           |
| 4   | 緊急招集 | 本番やCIに影響が出る                     | `#incident` チャンネルが自動でできて、参加者のアイコンが1人ずつ増える。電話も鳴る                                                                        |
| 5   | 伝説     | セキュリティ事故や取り返しのつかない損失 | 部長が**急に敬語になる**「少しお時間よろしいでしょうか」→ 暗転 → 社内報風のカード「その夜、何が起きたのか」→「※これは研修です」→ 先輩「な？ やるなよ？」 |

### 4.3 ヤバ度の計算

同じミスでも、どこまで広がったかでヤバ度が変わる。

```
ヤバ度 = ミスの重さ × 拡散段階 ＋ 時間帯補正（上限 Lv5）
```

| 拡散段階 | 内容                          |
| -------- | ----------------------------- |
| 0        | ローカルだけ                  |
| 1        | origin に push 済み           |
| 2        | 誰か（NPC）が pull 済み       |
| 3        | CI が走った／本番に反映された |
| 4        | 公開リポジトリに出た          |
- やらかしたあと、NPCがタイマーで pull し、CIも自動で走る。**放っておくとメーターがじわじわ上がる**ので、広がる前に止めるレースになる
- 時間帯補正：金曜17時以降とリリース前夜は +1
- 計算式の係数は未定（7章）

### 4.4 やらかし図鑑

「イベント」列は docs 02 の 3.1 のイベント名。★は今回新しく追加が必要なもの。

| やらかし                                 | ヤバ度（最小 → 最大）   | 復旧                                        | イベント                                      |
| ---------------------------------------- | ----------------------- | ------------------------------------------- | --------------------------------------------- |
| コミットメッセージの誤字や愚痴           | 1 → 3                   | amend、または謝る                           | ★`COMMIT_MESSAGE_FLAGGED`                     |
| node_modules をcommit                    | 1 → 2                   | `reset --soft`、`rm --cached`               | ★`IGNORED_PATTERN_COMMITTED`                  |
| commit済みの変更を `reset --hard`        | 2                       | reflog                                      | `COMMITS_ORPHANED`                            |
| **未commitの変更**を `reset --hard`      | 3（救えない）           | 救えないことを学ぶのが目的                  | `UNCOMMITTED_CHANGES_DISCARDED`               |
| 未マージのブランチを `branch -D`         | 2                       | reflog から復元                             | ★`UNMERGED_BRANCH_DELETED`                    |
| detached HEAD でcommitしてそのまま離れる | 2                       | reflog と `switch -c`                       | `DETACHED_HEAD_ENTERED`、`COMMITS_ORPHANED`   |
| main に直接 push して CI が赤            | 3                       | revert                                      | `DIRECT_PUSH_TO_PROTECTED`                    |
| コンフリクトマーカーごと push            | 2 → 4                   | 修正コミット                                | ★`CONFLICT_MARKER_COMMITTED`                  |
| force push で他人のコミットを消す        | 4                       | 相手のreflog、`--force-with-lease`          | `FORCE_PUSH_OVERWROTE`                        |
| 共有ブランチを rebase して force push    | 4                       | 同上                                        | `HISTORY_REWRITTEN_ON_SHARED_BRANCH`          |
| `.env` をcommit                          | 1 → 5（公開リポジトリ） | `rm --cached`、**キーを無効にして作り直す** | `SECRET_COMMITTED`、`SECRET_PUSHED`           |
| 顧客データの `dump.sql` をpush           | 5                       | 履歴から消すだけでは足りないことを学ぶ      | ★`SENSITIVE_DATA_PUSHED`                      |
| 金曜18:59に `push --force origin main`   | 5                       | 称号「金曜日の悪魔」                        | `FORCE_PUSH_OVERWROTE` ＋時間帯補正           |
| `rm -rf /`                               | 測定不能                | 部長がカットインで物理的に走ってくる        | ★`SHELL_CATASTROPHE`（docs 03 の 1.3 のネタ） |

### 4.5 やり込み要素

- **役満**：1行で複数のやらかしをまとめて起こすとボーナス。例：`git add . && git commit -m "fix" && git push -f origin main` で「.env混入＋main直push＋force」の三連
- **称号**：ヤバ度の合計で決まる。ヒヤリハット職人 → 始末書コレクター → 歩く障害報告書 → 伝説の人
- **ダサ度は別の軸にする**：無駄な操作（`fix` コミット30連など）はヤバ度0。そのかわり後輩の信頼が下がる（P5）
- 道場で集めたヤバ度の仕組みを、本編（2章や3章のシナリオ）でも同じメーターとして使う。道場で練習したことがそのまま本番で効いてくる

## 5. エンジンとの接続

- ヤバ度の判定は、エンジンが出す `events[]`（docs 02 の 3.1）を演出エンジンが受け取って計算する。エンジン側はヤバ度を知らない
- 拡散段階を上げるために、次のイベントも必要になる
  - ★`NPC_PULLED { repo, commits }`：NPCが危険なコミットを取り込んだ
  - ★`CI_RAN { commit, result }` ／ ★`DEPLOYED { commit }`：シナリオ側の擬似CIと擬似デプロイ
- 作中の時計（2.4）はコマンドの種類と結果（成功・エラー）から決まる。parse の結果に「状態を見るだけのコマンドか」の区分が必要
- 26時ステージの push の所要時間は、push するオブジェクトの総サイズから計算する
