## 1. 一番大事なこと（6つ）

| # | ルール | なぜ |
|---|---|---|
| G1 | **ターミナルの入力を演出で止めない** | 主役は学習者の手。演出は手を止めずに横で起きる。止めてよいのは雷のカットインだけ（2秒以内、キーを押せば飛ばせる） |
| G2 | **怒りは「短く・静かに・敬語に」なっていく** | 怒鳴り声、`！！！`、大きな赤文字は使わない。怖さは文字数の少なさと間で出す（04_spec_scenarios の P4） |
| G3 | **怒ったら必ず「なぜダメ？」と戻し方に行ける** | 怒られて終わると、ただの罰になる（04_spec_drama_system の §1） |
| G4 | **具体的な固有名を使う** | `file.txt` ではなく `src/payment/calc.ts`。`commit` ではなく `"ううう"`。「あるある」と感じた瞬間に覚える |
| G5 | **1シナリオで教えるのは1つだけ** | 26時ステージなら「pushする前なら、コミットは作り直せる」。ほかの学びは脇役にする |
| G6 | **ふだんの画面はとことん整える。散らかすのは、やらかしたときだけ** | 『Good Job!』（Switch）と同じ笑いの作り方。整っている世界ほど、めちゃくちゃになったときにおかしい（6章） |

## 2. 2つの仕様の食い違いをどう解くか（提案）

04_spec_drama_system の §11.5 で挙がっている2点への、演出側の答え。

### 2.1 評価軸：上司の機嫌は残す。ヤバ度は「事件の大きさの表示」にする

- ゲームの数値（ゲージ）は、実装済みの**上司の機嫌**と**後輩の信頼**の2本のままにする。3本目のゲージは増やさない
- ヤバ度は、**1件のやらかしごとのラベル**として使う
  - 危険のカットインに「Lv3 始末書」と出す
  - 始末書図鑑の各ページにヤバ度を載せる
- **始末書図鑑（drama §5）とやらかし図鑑（scenarios §4.4）は同じものにする**。名前は「始末書図鑑」に統一し、各ページにヤバ度の段階を持たせる
- 機嫌の減り方は、今の重さ（fatal / major / minor）のままでよい。ヤバ度の段階はおおむね次のように対応させる

| ヤバ度 | 名前 | 今の重さ |
|---|---|---|
| Lv1 | ヒヤリ | minor |
| Lv2 | 冷や汗 | minor〜major |
| Lv3 | 始末書 | major |
| Lv4 | 緊急招集 | fatal |
| Lv5 | 伝説 | fatal（秘密情報や顧客データ） |

- **ヤバ度は「損害額」でも見せる**（提案）。Lv ごとに目安の金額を決め、拡散段階が上がるたびに金額がカウントアップしていく
  - 例：node_modules をcommit ¥0 → `.env` を公開リポジトリにpush ¥48,000,000
  - 本編では結果画面にだけ出す。やらかし道場ではプレイ中も出し、**損害額を稼ぐのが目的**になる
  - 金額は笑えるくらい具体的に（「¥12,480」のように端数まで）。根拠は始末書に書く（調査の工数、キーの再発行、問い合わせ対応など）
- 拡散段階（NPCがpullした、CIが走った）でヤバ度が上がる仕組みは、`NPC_PULLED` などのイベントができてからでよい。それまでは種類ごとに固定のLvを使う
- Cue には、そのときに `report` へ `level` を足すだけで足りるはず（提案）

### 2.2 作中の時計：実時間を基本にし、コマンドの「所要時間」を足せるようにする

- 実装済みの「実時間で進む」を基本にする
- そのうえで、シナリオが**コマンドごとの所要時間**を足せるようにする（提案）

```
作中の時刻 = 開始時刻 ＋ 実時間 × clockScale ＋ コマンドの所要時間の合計
```

- 使いどころ：
  - 26時ステージで node_modules ごと push すると、18分ぶん時計が飛ぶ
  - ヒントを見ると5分飛ぶ（04_spec_scenarios の 2.4）
- 所要時間は入力のログ（コマンド列）から決まるので、決定性とリプレイは崩れない
- 時計が飛んだときは、数字をパラパラと早送りで回す（0.6秒ほど）。飛んだことが目で見てわかるようにする

## 3. キャラクターの声

セリフを書くときの決まり。`lines.ts` を差し替えるときの基準にする。

| | 後輩（田中） | 部長 | 先輩 |
|---|---|---|---|
| 立場 | 入社1年目。素直でよく見ている | 技術はいちばん正しい。口数が少ない | 3年上。軽いが頼れる |
| 話し方 | 丁寧語。心の声は `（ ）` で書く | 短い言い切り。怒るほど短くなり、最後は敬語 | タメ口。語尾がゆるい |
| 長さ | 20字以内 | 平常時は40字以内。怒るほど短く | 30字以内 |
| 使わない | 先輩をけなす言葉 | 人格否定、大声、`！` | 正解をそのまま言う（ヒントは方向だけ） |
| 例 | 「確認してから打つんですね」「（いまの、何が変わったんだろう）」 | 「"修正"って、何をだ」 → 「…ちょっといいか」 → 「少しお時間よろしいでしょうか」 | 「reflog って知ってる？」「`:wq` だよ…」 |

- **後輩の「無言」も演出に使う**：信頼が「虚無」の段階では、セリフを出さずに `typing`（入力中…が出ては消える）だけにする
- **部長が褒めるのはレアにする**：「…まあ、悪くない」「👍」だけ。言葉が少ないほど価値が出る

## 5. Cue を画面にするときの目安

| Cue | 見せ方 | 長さ | 注意 |
|---|---|---|---|
| `chat` | 吹き出しが下からポンと出る。直前に「入力中…」を `300ms + 1文字30ms`（最大1.2秒）出す | — | `whisper` は小さく薄い文字。`rage` も**色と大きさは変えない**。間（入力中の長さ）を倍にする |
| `face` | 上がるときは0.2秒でパッと変える。下がるときは0.8秒かけてゆっくり暗くする | 0.2〜0.8秒 | 表情はアイコンだけでなく、ヘッダーの小さな顔にも同時に出す |
| `mood` | 部長のアイコンの枠の色だけ変える。「爆発寸前」はアイコンが小さく震える | — | 機嫌の数値は出さない |
| `gauge` | 玉が1つずつ増える・減る。減るときは玉がしぼんで消える | 0.3秒 | 増減の数字（+5 など）は出さない。任天堂らしく「量」で見せる |
| `cutin` | 画面の下3分の1に帯で出す。全画面にするのは `thunder` だけ | 1.2秒（thunderは2秒） | キーを押せば飛ばせる。入力は止めない（thunder 以外） |
| `shake` | 1：2px、2：5px、3：10px で揺らす | 0.3秒 | `prefers-reduced-motion` のときは揺らさず、枠を一瞬赤くする |
| `typing` | 「入力中…」の点が3つ跳ねる。`vanish` なら1.5秒で消える | — | 消えたあと何も投稿されない、が演出の本体 |
| `report` | 右上に始末書のカードがすべり込み、図鑑のアイコンに赤い点がつく | 2秒 | 開くのは学習者が押したとき。勝手に開かない |
| `deadline` | warning：時計の数字がオレンジ。urgent：赤くなり、1秒ごとに小さく脈打つ。over：数字が赤のまま止まらず進む | — | 画面全体を赤くしない |
| `rank` | 結果画面。「かかった時間」「手数」「損害額」が1行ずつ出る → 部長のひとこと → ランクのハンコがポンと押される | 2.5秒 | 損害額が大きいほど、数字のカウントアップを長く、重くする。S のときだけ、きらきらを足す |

### 5.1 いくつも同時に来たとき

1つのコマンドで、複数の Cue が同時に出ることが多い。

- **順番**：`shake` → `cutin` → `chat` → `face` / `gauge` → `report`
- **cutin は同時に1つだけ**。2つ目は捨てて、チャットだけ流す
- **チャットは1コマンドにつき、1キャラ1つまで**。後輩と部長が両方しゃべるときは、部長を先にする（後輩はその反応になる）
- 学習者が次のコマンドを打ったら、まだ出ていない演出は**飛ばして最後の状態にする**。演出が溜まって、ゲームが遅れていくのが一番よくない

## 6. 見た目：『Good Job!』のように「整っているのに、めちゃくちゃにできる」

お手本は Switch の『Good Job!』。きれいに整ったオフィスで、仕事を真面目にこなすこともできるし、壁を壊して最短で片づけることもできる。最後に「かかった時間」と「損害額」で評価される。このアプリでいえば、整った画面が「オフィス」で、やらかしが「壁を壊す」にあたる。

### 6.1 ふだんの画面（整っている）

- **パステル寄りのやさしい色で、平らに塗る**。基調は白とうすいグレー。色は意味のあるところだけに使う（赤＝危険、緑＝前進、青＝ブランチ・origin）
- **形はシンプルに**：角の丸い四角と円だけで組む。線は太めに（1.5〜2.5px）。ボタンとチップは丸いピル型
- **すべてをグリッドにきっちりそろえる**。散らかったときとの落差を大きくするため
- **コミットは「玉」**：ふちのある丸いビーズを、レールの上に等間隔で並べる。追加されるときは少しはねる（拡大率 1.0 → 1.12 → 1.0、0.25秒）
- **ファイルは「箱」**：4領域ビュー（作業ツリー → ステージ → ローカル → リモート）では、ファイルを小さな段ボール箱として運ぶ。`add` で箱がステージの台に乗り、`commit` で箱がまとめて梱包され、`push` で origin へ送られる
- **キャラクターは丸い頭と点の目だけの、2頭身のシンプルな人形**。表情は目の形と、頭の上のマーク（`!` `?` `…` 汗）で出す
- **ターミナルだけ暗い色**にする。ここだけは「本物の道具」として扱い、文字も英語の本物の出力のまま。めちゃくちゃになっても、ターミナルだけは崩さない
- **プレイ中は数字より量**：ゲージは玉やブロックを並べる。点数や増減の数字は結果画面まで出さない（やらかし道場の損害額は例外）

### 6.2 やらかしたとき（めちゃくちゃになる）

やらかしは、画面の「もの」が物理的に崩れることで見せる。**崩れたものは、復旧するまでそのまま残す**。散らかった画面を元に戻すこと自体が、復旧のごほうびになる。

| やらかし | めちゃくちゃの見せ方 | 復旧したとき |
|---|---|---|
| node_modules をcommit | 12,483個の小さな箱がステージの台に流れ込み、パネルからあふれて下にこぼれる | 箱が吸い込まれるように消える |
| 4GBの動画をpush | 巨大な箱が origin への通り道に詰まり、ギチギチと少しずつ押し込まれる | 箱が後ろに抜けて、ポンと戻る |
| `reset --hard`（未commit） | 作業ツリーの箱が床に落ちて、ぺしゃんこにつぶれる | 戻らない。つぶれた箱はシナリオの最後まで残る |
| `reset --hard`（commit済み） | 玉がレールから外れて、グラフの下に転がり落ちる | reflog で玉がレールに引き上げられる |
| force push で他人のコミットを消す | origin のレールから他人の玉が弾き飛ばされ、画面の外へ飛んでいく。先輩の頭に `!` | 飛んでいった玉が戻ってきて、元の位置にはまる |
| コンフリクトマーカーごとpush | ファイルの箱から `<<<<<<<` の矢印が飛び出して刺さったまま | 矢印を抜くように消える |
| detached HEAD でcommitして離れる | レールのない宙に玉が浮いたまま、ゆっくり遠ざかる | `switch -c` で新しいレールが伸びて、玉をつかまえる |
| `.env` をpush | 箱のふたが開き、鍵のアイコンが origin の向こうへばらまかれる。損害額のカウンターが回り始める | 鍵に×がつく（キーを無効にした）。ばらまかれた鍵は残る＝漏れたものは戻らない |
| `rm -rf /` | 画面のパネルが1枚ずつ倒れていく。ターミナルだけが残る | 部長が走ってきて、パネルを1枚ずつ起こす |

- **周りの反応は淡々と**：めちゃくちゃになっても、キャラクターは頭の上に `!` を出すくらい。大騒ぎしないほうがおかしい（G2 の「静かに怒る」とも合う）
- 物理演算のライブラリは使わず、Motion のアニメーション（落下、跳ね返り、回転）で十分。決まった動きにしておくと、リプレイでも同じ崩れ方になる
- `prefers-reduced-motion` のときは、崩れる動きを省き、崩れた後の状態だけ見せる

### 6.3 音（任意）

- 効果音は短く1つずつ：前進「ポン」、エラー「ブッ」（小さく）、危険「ガシャーン」、始末書「ペラッ」、損害額のカウントアップ「チャリチャリ」
- BGMは軽いオフィス風。時計が urgent になったら少し速くする程度

## 7. シナリオを書くときの型

`scenarios/<id>/` に置くとき、次の5段で組み立てる。

| 段 | 中身 | 目安 |
|---|---|---|
| 1. 導入 | 状況をチャット3つ以内で伝える。時刻とファイル名を必ず入れる | 学習者が**20秒以内に最初のコマンドを打てる**こと |
| 2. 事件 | 強制のやらかし（カットシーン）か、NPCの操作で問題が起きる | ターミナルに本物の出力を出す |
| 3. 誘導 | 先輩のヒント、補助チップ、後輩の質問で方向だけ示す | 正解のコマンドは書かない |
| 4. 解決 | ゴール条件を満たす | par は作者の解答手順で決め、突き合わせテストに通す |
| 5. 余韻 | エンディングの一言（部長の「👍」など）と始末書 | ランクより先に、物語の結末を見せる |

- **NPCは学習者の手が止まっているときに動かす**。カットインや入力の最中に、裏でNPCがpushすると何が起きたかわからなくなる
- **やらかしの後に、必ず戻れる道を用意する**。戻れない失敗（未commitの変更を消すなど）は、「戻れない」ことを始末書で教えたうえで、チェックポイントから再開させる
- **セリフは `lines.ja.ts` に、ロジックは `scenario.ts` に**（05_spec_tech_stack の構成どおり）。演出側が文言だけ直せるようにする

## 9. やってはいけないこと

- 実在の会社名、サービス名、人名を NPC やファイル名に使う
- 眠気のタイポで、**実際に打ったコマンドを書き換える**。タイポは見た目だけにし、Enter で実行されるのは学習者が打った文字列にする（入れるなら、設定で切れるようにする）
- 観測コマンド（`status` / `log`）を打ったことに、どんな形でも罰を与える
- 演出が終わるまで、次のコマンドを打てなくする（雷を除く）
- Lv5（秘密情報、顧客データ）を笑いだけで終わらせる。最後は「キーを無効にする」「報告する」といった現実の対応を見せる
